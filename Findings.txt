Finding: Overly Permissive Policy Rules

Python:
	python check_permissive_policies.py

python script runs this and then parses it:
aws iam get-account-authorization-details --profile PROFILE_NAME --output json > iam_dump.json
	returns every policy with a wildcard ( * )

Then grep for the dangerous patterns:
	Service-level wildcards (s3:*, ec2:*, iam:*, etc.)
	grep -n ":\*" iam_dump.json

	Unrestricted resources
	grep -n "\"Resource\": \"\*\"" iam_dump.json

	Inline policies with overly broad access
	grep -A5 -B5 "\"Effect\": \"Allow\"" iam_dump.json | grep -B5 "\*"

What "overly permissive" looks like:
┌────────────────────────────────────────────────┬────────────────────────────────┐
│                    Pattern                     │              Risk              │
├────────────────────────────────────────────────┼────────────────────────────────┤
│ "Action": "*", "Resource": "*"                 │ Full admin                     │
├────────────────────────────────────────────────┼────────────────────────────────┤
│ "Action": "iam:*"                              │ Can escalate to admin          │
├────────────────────────────────────────────────┼────────────────────────────────┤
│ "Action": "sts:AssumeRole", "Resource": "*"    │ Can assume any role            │
├────────────────────────────────────────────────┼────────────────────────────────┤
│ "Action": "s3:*"                               │ Full S3 access, data exfil     │
├────────────────────────────────────────────────┼────────────────────────────────┤
│ "Action": "lambda:*"                           │ Code execution, priv esc       │
├────────────────────────────────────────────────┼────────────────────────────────┤
│ "Action": ["ec2:RunInstances", "iam:PassRole"] │ Launch instance with any role  │
├────────────────────────────────────────────────┼────────────────────────────────┤
│ No Condition block on sensitive actions        │ Missing MFA/IP/tag constraints │
└────────────────────────────────────────────────┴────────────────────────────────┘

Weak RDS Configuration 

Python:
	check_rds.py


Evidence:

	Check for SSL/TLS not being enforced (rds.force_ssl is not set):
	first get the parameter groups in use, then check each one:
		aws rds describe-db-instances --profile PROFILE_NAME --query "DBInstances[].{Instance:DBInstanceIdentifier,Engine:Engine,ParamGroup:DBParameterGroups[0].DBParameterGroupName}" --output table

	Then for each parameter group:
	aws rds describe-db-cluster-parameters --db-cluster-parameter-group-name PARAM_GROUP_NAME --profile PROFILE_NAME --query "Parameters[?ParameterName=='rds.force_ssl'].{Name:ParameterName,Value:ParameterValue}" --output table

	For MySQL/MariaDB instances use require_secure_transport instead:
		aws rds describe-db-cluster-parameters --db-cluster-parameter-group-name default.aurora-mysql5.7 --profile growth_prod --query "Parameters[?ParameterName=='require_secure_transport'].{Name:ParameterName,Value:ParameterValue}" --output table

		- Value = 0 or empty → SSL not enforced (finding)
		- Value = 1 → SSL enforced (good)


	Check for default master username:
		aws rds describe-db-instances --profile PROFILE_NAME --query "DBInstances[].{Instance:DBInstanceIdentifier,MasterUsername:MasterUsername,Engine:Engine}" --output table


	No Audit logging:
		aws rds describe-db-instances --db-instance-identifier INSTANCE_NAME --profile PROFILE_NAME --query "DBInstances[].{Instance:DBInstanceIdentifier,Engine:Engine,LogExports:EnabledCloudwatchLogsExports}" --output table
	or if cluster:
		aws rds describe-db-clusters --db-cluster-identifier INSTANCE_NAME --profile PROFILE_NAME --query "DBClusters[].{Cluster:DBClusterIdentifier,Engine:Engine,LogExports:EnabledCloudwatchLogsExports}" --output table
	
	If LogExports is empty/None — no audit logging. If populated, it shows which logs are exported (e.g., audit, error, general, slowquery for MySQL or postgresql for Postgres)


	Check for enhanced monitoring:
	aws rds describe-db-instances --profile PROFILE_NAME --query "DBInstances[].{ID:DBInstanceIdentifier,MonitoringInterval:MonitoringInterval}" --output table

		- MonitoringInterval = 0 → Enhanced monitoring disabled
		- MonitoringInterval = 1/5/10/15/30/60 → Enabled, collecting metrics every N seconds
		- MonitoringRoleArn = None → No IAM role assigned for monitoring


	Backups disabled:
		aws rds describe-db-instances --db-instance-identifier INSTANCE_NAME --profile PROFILE_NAME --query "DBInstances[].{Instance:DBInstanceIdentifier,BackupRetention:BackupRetentionPeriod}" --output table

		for Aurora clusters:
		aws rds describe-db-clusters --db-cluster-identifier CLUSTER_NAME --profile PROFILE_NAME --query "DBClusters[].{Cluster:DBClusterIdentifier,BackupRetention:BackupRetentionPeriod}" --output table

		0 = backups disabled. Any other number = days backups are retained.


	Deletion protection:
	aws rds describe-db-instances --profile PROFILE_NAME --query "DBInstances[].{Instance:DBInstanceIdentifier,DeletionProtection:DeletionProtection,Engine:Engine,Status:DBInstanceStatus}" --output table
		False = no deletion protection, anyone with rds:DeleteDBInstance permission can delete it.


	Show engine versions:
		aws rds describe-db-instances --profile PROFILE_NAME --query "DBInstances[].{Instance:DBInstanceIdentifier,Engine:Engine,Version:EngineVersion,AutoUpgrade:AutoMinorVersionUpgrade}" --output table
